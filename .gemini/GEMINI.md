# [헌법] 프로젝트 개발 및 품질 관리 규칙

## 1. 개요 및 철학
본 규칙은 웹, 앱, AI, 백엔드 등 모든 소프트웨어 엔지니어링 프로젝트의 **무결함 개발**과 **높은 사용자 가치**를 실현하기 위한 엄격한 6단계 공정입니다. 모든 작업은 지정된 명령어로 시작하며, 각 단계의 산출물(`.md`)이 완벽히 존재해야 다음 단계로 진행할 수 있습니다.

## 2. 프로젝트 기본 설정 (Local Project Context)
- **노드 버전:** node 20.20.2 버전을 사용한다.
- **프로젝트 컨셉:** 해당 프로젝트는 공부 관련 프로그램 블로그 이다.
- **특성:** 프로젝트는 화면이 끊기면 안되게 구성한다.
- **서브에이전트·메인 분업 (용어):** **서브 컨텍스트**로 부르는 맥락(검증 결과를 메인에게 넘기는 방식)과 보고서 형식은 **`subagent-handoff.mdc`** 에 정리되어 있다. 서브는 조사 위주, 코드 수정은 메인이 담당한다.

## 3. 6단계 표준 워크플로우 (Standard Workflow)

### 1단계: 전략 수립 및 계획 (`/nh:plan`)
- **설정:** `.gemini/configs/plan_rules.md`
- **목표:** 비즈니스 요구사항 분석, 기술 스택 선정, 시스템 아키텍처 타당성 검토.
- **산출물:** `plan.md`

### 2단계: 기술 설계 및 인터페이스 (`/nh:add`)
- **설정:** `.gemini/configs/add_rules.md`
- **목표:** 클래스 다이어그램, 데이터 모델링, API 명세, 구현 블루프린트 작성.
- **산출물:** `add.md`

### 3단계: 무결점 구현 (`/nh:make`)
- **설정:** `.gemini/configs/make_rules.md`
- **목표:** 설계 기반 소스 코드 작성, 클린 코드 원칙 준수, 디자인/에셋 연동.
- **산출물:** `make.md` (및 소스 코드 전체)

### 4단계: 가치 검증 및 사용자 경험 (`/nh:fun`)
- **설정:** `.gemini/configs/fun_rules.md`
- **목표:** 스토리텔링, UX/UI의 재미 및 몰입도, 비즈니스 가치 및 혁신성 검증.
- **산출물:** `fun.md`

### 5단계: 품질 감사 및 보안 검토 (`/nh:qa`)
- **설정:** `.gemini/configs/qa_rules.md`
- **목표:** 정적 분석(Lint), 런타임 안정성, 보안 취약점, 최종 기술 점수 평가.
- **산출물:** `qa.md`, `game_map.md` (또는 `system_map.md`)

### 6단계: 최종 결과 정리 (`/nh:result`)
- **설정:** `.gemini/configs/result_rules.md`
- **목표:** 단계별 결과물, 게임 구성도, 아키텍처 구성도를 최종 패키지로 정리.
- **산출물:** `result.md`, `result.html`

## 4. 공통 준수 사항
- **순차적 기록:** 단계 건너뛰기는 금지됩니다. (1->2->3->4->5->6 순서 필수)
- **작업 추적:** 현재 어떤 워크플로우가 진행중인지 `.gemini/plan/task.md` 에 기록되어야 한다.
- **에이전트 페르소나:** 서브 에이전트는 각 설정 파일에 명시된 전문 역할을 충실히 수행합니다.
- **한국어 원칙:** 모든 소통과 문서는 한국어로 작성합니다.
- **엄격한 피드백:** QA 점수가 기준점(0.95) 미만일 경우, 에이전트는 즉시 'No-Go' 판정을 내리고 개발 단계로 환류시킵니다.
